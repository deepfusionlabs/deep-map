---
description: Upgrade DeepMap to the latest version. Refreshes the marketplace and updates the plugin for you through the `claude` CLI (in any host that has one), checks the new version landed, then tells you how to load it. `/deep-map:plugin-update --check` reports installed vs newest (it refreshes the marketplace catalog and installs nothing).
argument-hint: "[--check]"
disable-model-invocation: true
---

Bring the running DeepMap up to date. `claude plugin update` fetches the newest version (it refreshes a git marketplace first), but nothing inside a session runs it, checks that it landed and says how to load it; this command does (the feature request, [anthropics/claude-code#38271](https://github.com/anthropics/claude-code/issues/38271), was auto-closed as stale). Only the user can start it (it is not model-invocable), so **when they run it, that is the request to update: do the work; do not stop to ask for a second yes.** It changes only Claude Code's plugin files (`~/.claude/plugins/`, or under `$CLAUDE_CONFIG_DIR` when that is set), never the user's repositories or git. There is no one-command rollback: the previous version stays in the plugin cache only for a limited time (14 days on current Claude Code releases, 7 on older ones, longer while a running session still uses it), after which Claude Code deletes it.

**`--check`** (in `$ARGUMENTS`): do steps 1–3 only. It installs nothing; its catalog refresh does update Claude Code's local copy of the marketplace catalog.

1. **Find a working `claude` CLI through your shell tool, in every host; prefer the Bash tool, because only it exports `$CLAUDE_CODE_EXECPATH` (the PowerShell tool does not).** The terminal CLI, the VS Code / JetBrains extensions and the desktop app all give you a shell tool that can run it. A candidate is usable only if `<claude> plugin update --help` prints `Usage: claude plugin update` (an unknown subcommand exits 0 too, so the exit code proves nothing). In PowerShell, call a path with `&`: `& "<path>" plugin update --help`.
   - `"$CLAUDE_CODE_EXECPATH"`: the exact binary running this session; if it is usable, use it and skip the rest;
   - every `claude` on PATH: `type -ap claude` in bash; in PowerShell `Get-Command claude -All` or `where.exe claude` (plain `where` is PowerShell's `Where-Object` alias and finds nothing);
   - the CLI bundled with an IDE extension, `~/.vscode/extensions/anthropic.claude-code-*/resources/native-binary/claude` (`claude.exe` on Windows; also under `~/.vscode-insiders/`, `~/.cursor/`, `~/.windsurf/`), or with the desktop app (Windows: `%APPDATA%\Claude\claude-code\<version>\claude.exe`).

   Without a usable `$CLAUDE_CODE_EXECPATH`, run `<claude> --version` on every usable PATH and bundled candidate and take the **highest version number**, compared numerically, never a PATH hit just because it comes first (an old global install can sit on PATH). If a later step fails with the chosen CLI, try the next-highest before giving up.

   **None works** → with `--check`, say no `claude` CLI is reachable, report the installed version from `installed_plugins.json` (step 2) and the newest from the marketplace clone's `.claude-plugin/plugin.json` under `${CLAUDE_CONFIG_DIR:-~/.claude}/plugins/marketplaces/<marketplace>/` without refreshing it, and stop. Otherwise use the in-app manager: `/plugin` → **Marketplaces** → `<marketplace>` → **Refresh marketplace** (VS Code extension) / **Update marketplace** (terminal), then the installed **`deep-map`** plugin (the **Plugins** tab in the VS Code extension, **Installed** in the terminal) → **Update plugin** / **Update now**; then go to step 5.

2. **Resolve the install.** Run `<claude> plugin list --json` (it honours `$CLAUDE_CONFIG_DIR`) and take the `deep-map@<marketplace>` entry, normally **`deep-map@deepfusionlabs-deep-map`** (the plugin's name is `deep-map`, with a hyphen; the catalog's is `deepfusionlabs-deep-map`). There can be one install per scope; use the one Claude Code applies here: a `local`, then a `project` entry whose `projectPath` is this project (or its git root), else the `user` entry. Note its version, scope and install path. On a CLI without `--json`, read `installed_plugins.json` under `${CLAUDE_CONFIG_DIR:-~/.claude}/plugins/` (each key maps to an **array** of installs).
   - **No such entry, and this session runs from a local clone of the DeepMap repository** (the plugin loads from your working copy, e.g. `claude --plugin-dir`) → there is nothing to fetch; go to step 5 (a reload picks up your local edits).
   - **No such entry otherwise** → say DeepMap is not installed from a marketplace here and stop.

3. **Refresh the catalog, then find the newest version.** Run `<claude> plugin marketplace update <marketplace>` FIRST: `claude plugin update` refreshes the catalog itself, but when that refresh fails it only warns and, against the stale catalog, reports the installed version as the newest with exit 0; a separate refresh makes a failure visible. If the refresh fails, show its output and stop: without a fresh catalog the update cannot find a newer version. Then read the newest version from the marketplace's `.claude-plugin/plugin.json` (its location is `installLocation` in `<claude> plugin marketplace list --json`). If it equals the installed version, say it is already up to date (with `--check`, report and stop here either way).

4. **Update, then verify it landed.** Run, from this project's directory, always passing the scope from step 2 (without `--scope`, a current CLI updates whichever install applies to the current directory, which need not be the entry you resolved):
   ```
   <claude> plugin update deep-map@<marketplace> --scope <scope>
   ```
   Then run `<claude> plugin list --json` again: the entry must now show the newest version from step 3, and its install path must exist with that version in `.claude-plugin/plugin.json` (do not go by the recorded git commit: it can stay at the old one). If the version did not move, refresh the marketplace and update once more; if it still did not move, show the exact CLI output and fall back to the `/plugin` manager (step 1). Report **old → new**.

5. **Load it: the one step left for the user.** The new version is **on disk** but not yet running: Claude Code loads a plugin when a session starts, and chats already open keep their version after a CLI update (an update made in the VS Code extension's Manage Plugins dialog reloads open chats in place). Depending on the host:
   - **VS Code / JetBrains extension** → open a **new chat**: a new session loads the installed version, while this chat keeps the version it started with. A full IDE restart also works, but it ends every running Claude session in every window.
   - **Terminal CLI** → start a **new session** (the sure path), or run **`/reload-plugins`** (older releases did not rebuild the slash-command index on a reload, [#37862](https://github.com/anthropics/claude-code/issues/37862)).
   - **Desktop app / web** → start a new session, or restart the app.

6. **Confirm it flipped.** In the new session, run **`/deep-map:version`**: the **LOADED** line should equal the installed version (it reports what is actually running, so it is the honest check that activation worked).

7. **Move each project's DeepMap servers onto the new version.** A project's MCP search/embed servers are long-running **detached** processes started from the plugin directory of the version that launched them, so after an update they keep running the **previous version's code** until they restart, so a fix in the search server or retriever does not reach you until then, even though `/deep-map:version` already shows the new version. The next session start in a project restarts that project's own servers on the new version in the background (the SessionStart heal, unless `DEEPMAP_HEAL=0`; it also recognises servers an older DeepMap version started, and a Claude Code window still open on the previous version never moves them back to it). To do it at once, run **`/deep-map:setup`** in that project: it restarts that project's own servers from the new version (it never touches another project's). Either way, have the user run **`/mcp`** and reconnect `deepmap-search` / `deepmap-embed` (or reload), because the client's connection to the old server ends when it is replaced (a note at session start, or at the first search after the restart, says so).
